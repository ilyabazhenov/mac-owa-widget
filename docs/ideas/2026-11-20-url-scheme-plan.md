# План: URL-схема `owawidget://`

Запрос пользователя (2026-11-20): личный ассистент шлёт уведомления macOS о важных письмах и встречах, клик должен открывать письмо в OWA Widget. Сейчас снаружи окно почты открывается только горячей клавишей Ctrl+Option+M.

План прошёл ревью по коду; исправления ревью уже внесены.

## Этап 1 — почта

### Маршруты

Только навигация, ничего не меняют в ящике (кроме обычной отметки «прочитано», см. «Риски»).

| URL | Что делает |
|---|---|
| `owawidget://mail` | открывает окно почты и выводит его на передний план |
| `owawidget://thread?id=<id>` | открывает беседу |
| `owawidget://message?id=<id>` | открывает беседу письма, разворачивает письмо и прокручивает к нему |
| `&account=<account_id>` | необязательный; нужен при нескольких аккаунтах |

`id` — полный EWS id (закодированный для URL) или короткий хэш из ответа MCP.

Dev-сборка (`make run`, bundle id `….dev`) регистрирует схему `owawidget-dev`, чтобы у пользователя с двумя копиями приложения Launch Services не выбирал случайную.

### Шаги

0. **Проверка приёма URL.** Пустой обработчик `kAEGetURL` в `AppDelegate.applicationWillFinishLaunching`: убедиться, что SwiftUI его не перехватывает и не открывает лишнее окно (у приложения только `MenuBarExtra` и сцены `Window`). Если не выходит — запасной путь `application(_:open:)`.
1. **Модель маршрута** — `OWAWidget/Services/AppURLRoute.swift`. Чистый парсер `URL → AppURLRoute?` без AppKit: белый список хостов и параметров, проверка длины id, неизвестное отвергается. Принимает обе схемы (`owawidget`, `owawidget-dev`).
2. **Схема в бандле.** `CFBundleURLTypes` → `owawidget` в `OWAWidget/Info.plist`; в `Makefile` для dev-сборки PlistBuddy меняет схему на `owawidget-dev` (рядом с подменой `CFBundleIdentifier`).
3. **`AppURLRouter`** (`@MainActor`). Принимает маршрут от обработчика Apple Event. Холодный старт: URL приходит раньше, чем строка меню и `MailService` готовы (`onChange(of: openRequest)` в `MenuBarLabelView` до появления метки не сработает), поэтому роутер держит отложенный маршрут и выполняет его на хуке, где стартует MCP (`setupGlobalHotkeyJoin` в `OWAWidgetApp`).
4. **Открытие через готовый путь:** `mailService.open(conversationID:)` → `MenuBarLabelView` (`openWindow(id: "mail")`) → `consumeOpenRequest()`. Так же работают клики по уведомлениям о новых письмах. Добавить:
   - `MailOpenRequest.focusMessageID`: `MailWindowModel.openConversation` разворачивает это письмо и прокручивает к нему, а не только непрочитанные и самое новое;
   - `message?id`: письмо → беседа через уже существующий `MailService.fullMessage` (там `conversationID`, проверки `blocksSync` и `reportExternalRequestFailure` уже есть — новый запрос не нужен);
   - **если письма нет в загруженной беседе** (например, оно в «Удалённых»: `MailService.thread()` по умолчанию их пропускает), открыть само письмо через `messageThread(ref)`;
   - проверить, что свёрнутое или спрятанное окно поднимается; если `openWindow` этого не делает — `deminiaturize` + `orderFrontRegardless`.
5. **Короткие хэши.** Таблица одна на приложение (`MCPMailTools` внутри `MCPServerService.shared`, 2000 записей, только в памяти): хэш живёт часами и теряется только при перезапуске. Роутер разрешает его через `MCPServerService` (`resolve`); полный id (> 20 символов) принимается как есть.
6. **MCP.**
   - `open_url` с полным id — только в `get_mail_message` и `get_mail_thread`. В списках (`list_mail`, `search_mail`, `get_mail_digest`) не отдаём: полный id ~170 символов на строку раздул бы ответ, а размер ответов MCP ограничен.
   - В описаниях списочных инструментов — шаблон `owawidget://thread?id=<thread_id>` (короткий хэш годится).
   - Схема в `open_url` берётся из `Bundle.main` (`CFBundleURLSchemes`), не из кода: иначе dev-сборка раздавала бы ссылки на релизную копию.
   - `account` в `open_url` — только при нескольких почтовых аккаунтах.
7. **Ошибки без утечек.**
   - Почта выключена или аккаунта нет → окно не открывается (как и горячая клавиша), только запись в `DiagnosticLog`.
   - Письмо не найдено (хэш потерян после перезапуска, неверный id) → окно открывается, уведомление «Письмо не найдено — попросите ассистента ссылку заново».
   - Ссылка на аккаунт, отличный от открытого в окне (`service.account`) → окно открывается, уведомление; аккаунт не переключаем.
   - Строки уведомлений — ru и en через `LocalizationService`. Наружу никакие данные не уходят.
8. **Тесты** (`Tests/OWAWidgetTests`):
   - парсер: валидные и мусорные URL, кодировка `+/=`, длинный id, неизвестный хост и схема;
   - разрешение хэша и полного id;
   - `open_url` в `get_mail_message` / `get_mail_thread`, его отсутствие в списках, схема из бандла;
   - `focusMessageID` и откат на `messageThread` на `FakeMailProvider`.
9. **Документация.**
   - `README.md` / `README.ru.md`: маршруты, пример уведомления с `terminal-notifier -open 'owawidget://message?id=…'` (у `osascript display notification` клик URL не открывает), честная оговорка про отметку прочитанным.
   - `AGENTS.md`: абзац про схему, правило «только навигация», dev-схему.
   - Упоминание в `docs/superpowers/specs/2026-10-17-mail-design.md`.
10. **Проверка.** `swift build`, `swift test`; затем `make run` (перед этим спросить и закрыть запущенную `.build`-копию — `make run` её перезаписывает) и `open 'owawidget-dev://…'` в трёх случаях: приложение запущено, окно спрятано/свёрнуто, приложение закрыто.

## Этап 2 — встречи (`owawidget://event?id=`), отложен

Хэши встреч не зависят от памяти (`MCPEventID.short` сверяется со списком событий), ссылки стабильны в пределах окна синка. Сложность — открыть поповер `MenuBarExtra` программно: публичного API нет. Варианты: выбрать встречу через `PopoverView.selectEvent` и открыть поповер кликом по кнопке status item (хрупко) или показать встречу в отдельной панели. Решить после этапа 1.

## Риски и решения

- **Безопасность.** Ссылку может вызвать любая страница или приложение. Через схему нельзя ни отправить, ни создать черновик, ни отменить что-либо; параметры строго проверяются.
- **Отметка прочитанным.** Открытие беседы по ссылке ведёт себя как ручное: `scheduleMarkRead` по настройке `mailMarkReadMode` отмечает прочитанными все непрочитанные письма беседы, не одно. Браузер спрашивает перед переходом по внешней схеме; считаем допустимым и пишем об этом в README.
- **Один аккаунт в окне.** Ссылку на письмо другого аккаунта на этапе 1 не открываем — уведомление.
